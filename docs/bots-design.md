# Bots design (contract for all workstreams)

Users with `ManageBots` create bots in Workspace settings -> Bots. A bot is written in TypeScript or Python, stored in Convex, and run by a separate, locked-down `bot-runner` container. A bot acts like a member: it calls the same Convex functions (`messages:send`, `messages:list`, `reactions:toggle`, ...) with its own identity. **All of its permissions are off until an admin grants them.**

```
 browser UI ──Convex──▶ bots.* (CRUD, files, perms, env, logs)
                              │
 bot-runner ──HTTP──▶ /bots/runner/*  (desired state, bundle, credential, report, logs)
    │ spawns one process per enabled bot (own uid, own dir, limits)
    ▼
 bot process + SDK ──HTTP──▶ POST /bots/token  (API token -> 1h JWT)
                    ──HTTP──▶ Convex /api/query|mutation with Bearer JWT (same functions people use)
                    ──poll──▶ botEvents:poll  (new messages / reactions the bot may see)
```

## Identity

* Bot user id `bot_<botDocId>` = `bots.userId` = JWT `sub`. Every bot has a `members` row (`userId`, `nickname = name`, `roleIds = []`), so mentions, `requireMember`, author lookups and member lists work unchanged.
* JWT: ES256, claims `iss = BOT_JWT_ISSUER`, `aud = BOT_JWT_AUDIENCE`, `sub = bot userId`, `iat`, `exp = iat + BOT_JWT_TTL_SECONDS`, header `kid`. Constants live in `packages/core/src/bots.ts`.
* Convex trusts it through a second provider in `auth.config.ts` (`type: "customJwt"`, `applicationID = BOT_JWT_AUDIENCE`, `issuer = BOT_JWT_ISSUER`, `algorithm = "ES256"`, `jwks` = data URI of `{"keys":[BOT_JWT_PUBLIC_JWK]}`), added only when `BOT_JWT_PUBLIC_JWK` is set. Without the env vars the feature is dormant and the UI says so.
* Deployment env (generated by `setup`, never by hand): `BOT_JWT_PRIVATE_JWK` (secret, ES256 JWK with `kid`), `BOT_JWT_PUBLIC_JWK`, `BOT_RUNNER_TOKEN` (secret, 48 random bytes base64url; shared with the runner container).
* API tokens: `abt_` + 43 base64url chars. Only SHA-256 hex is stored (`bots.tokenHash` external token, `bots.hostedTokenHash` runner-injected token). Compare hashes via index lookup, never `===` on token strings.

## Permissions

* `Permission.ManageBots` (bit 40) gates every `bots.*` function and the bot UI. Workspace owner has it implicitly.
* A bot does **not** inherit `@everyone`. `loadPermissionContext(ctx, botUserId)` returns one synthetic role `{ id: "@bot", position: 0, permissions: bot.grants }`, `roleIds: ["@bot"]`, `isOwner: false`. For a disabled bot it throws `ConvexError("Bot is disabled")`.
* `grants` can only contain `BOT_GRANTABLE_PERMISSIONS` (core). `Administrator`, `ManageRoles`, `ManageWorkspace`, `ManageBots`, `CreateInvites`, `DeleteInvites`, `ViewAuditLog` are never grantable.
* Granter ceiling: `requireCanGrant(granterContext, grants)` — a non-owner cannot give a bot a permission they lack.
* Channel result for a bot = `resolvePermissions(...) & grants`, and `0n` when `allowedChannelIds` is set and does not include the channel. So channel overrides can narrow a bot but never exceed `grants`.
* New bots start `enabled: false`, `grants: 0n`, `allowedChannelIds` unset (all channels the grants reach).
* Bots excluded from: license MAU/seat counting (`recordLicenseActivity`, `recordLogin`), role assignment/moderation targets are unaffected.

## Convex API

Management (UI): `packages/convex/convex/bots.ts` — contract in that file and `lib/botTypes.ts`. Audit actions: `bot.create`, `bot.update`, `bot.permissions`, `bot.files`, `bot.env`, `bot.token.rotate`, `bot.token.revoke`, `bot.delete` (names/ids only, never file content, env values or tokens).

Limits (`BOT_LIMITS` in core): 25 bots, 50 files, 256 KiB per file, 1 MiB total, 32 env vars, 4 KiB per env value, name 1..32 chars, description ≤ 200, 500 retained log lines per bot, 4 KiB per log line. File paths: relative, `[A-Za-z0-9._/-]`, no `..`, no leading `/` or `.`-only segments, no `node_modules/`, ≤ 128 chars. Env names `^[A-Z_][A-Z0-9_]*$`, must not start with `AULORA_`. Saving files, env, language or enabled bumps `revision`; `restart` bumps `restartNonce`.

Bot-facing events: `botEvents:poll({ cursor, limit? })` (query; caller must be a bot). `cursor: null` returns no events and a cursor of "now". Otherwise returns events with `seq > cursor`, ascending, at most `limit` (default 100, max 200), only for channels where the bot holds `ViewChannel` and `ReadHistory` (and is in `allowedChannelIds`). Message bodies are opened (decrypted) at read time; `message.deleted` has empty `body`. Shapes: `BotPollResult` / `BotEvent` in `lib/botTypes.ts`.

Emission: `lib/botEvents.ts` exports `emitBotEvent(ctx, event)`; it is a no-op unless some bot is `enabled` (one indexed read). Called from every path that creates/edits/deletes a message or adds/removes a reaction. Retention: `botEvents:prune` cron, hourly, deletes events older than 1 hour.

Everything else a bot does uses existing functions with its JWT: `channels:list`, `messages:list`, `messages:send`, `messages:edit`, `messages:remove`, `reactions:toggle`, `members:list`, files, threads, pins. Server-side permission checks apply exactly as for a person.

`members:list` rows get `isBot: boolean`; display name for a bot id comes from the `bots` table (see `lib/accountNames.ts`). Messages from a deleted bot keep their `authorId`.

## HTTP (Convex site origin, `botHttp.ts`)

`POST /bots/token` — header `Authorization: Bot <token>`; returns `200 {"token": "<jwt>", "expiresAt": <ms>, "userId": "...", "botId": "...", "name": "..."}`. `401 {"error":"invalid_token"}` for unknown token, `403 {"error":"bot_disabled"}`, `503 {"error":"bots_unavailable"}` when the JWT env is missing, `429` when rate limited (60/min per token hash). Either the external token or the hosted token works.

Runner API — header `Authorization: Bearer <BOT_RUNNER_TOKEN>` (constant-time compare; `503` when unset, `401` when wrong). All bodies JSON.

| Route | Request | Response |
| --- | --- | --- |
| `GET /bots/runner/desired` | – | `{"bots":[{"botId","userId","name","language","entry","revision","restartNonce"}]}` enabled bots only; records runner heartbeat |
| `GET /bots/runner/bundle?botId=` | – | `{"botId","userId","name","language","entry","revision","files":[{"path","content"}],"env":{"NAME":"value"}}`; `404` unknown/disabled |
| `POST /bots/runner/credential` | `{"botId"}` | `{"token":"abt_..."}` rotates `hostedTokenHash`; enabled bots only |
| `POST /bots/runner/report` | `{"botId","status":"starting"\|"running"\|"stopped"\|"crashed","message"?}` | `{"ok":true}` |
| `POST /bots/runner/logs` | `{"botId","lines":[{"stream","text","at"}]}` (≤ 200 lines, text clipped to 4 KiB) | `{"ok":true}`; keeps newest 500 lines per bot |

`entry` is `main.ts` for TypeScript and `main.py` for Python (`BOT_ENTRY_FILES`).

## Runner (`infra/bot-runner`, image `infra/docker/bot-runner.Dockerfile`, compose profile `bots`)

Plain Node ESM (`.mjs`, no deps), tests with `node --test`. Loop every 3 s: `GET desired`, reconcile (start missing, stop removed/disabled, relaunch when `revision` or `restartNonce` changed), restart crashed bots with exponential backoff (1 s .. 60 s; reset after 60 s of uptime). Per launch: fetch bundle, write files to `/work/<botId>/` (tmpfs), mint hosted credential, optionally install deps (`requirements.txt` -> `pip install --target .deps`; `package.json` -> `npm install --omit=dev --ignore-scripts`; 120 s timeout), spawn with a **fresh environment** (never the runner's), its own uid/gid, `cwd` = its dir (mode 0700), rlimits (nproc, memory, cpu-time off, file size), and capture stdout/stderr into batched log posts. Child env: `AULORA_TOKEN`, `AULORA_SITE_URL` (`CONVEX_HTTP_URL`), `AULORA_CONVEX_URL` (`CONVEX_SELF_HOSTED_URL`), `AULORA_BOT_ID`, `AULORA_BOT_USER_ID`, `AULORA_BOT_NAME`, plus the bot's own env vars, plus `PATH`, `HOME=/work/<botId>`, `LANG`.

Commands: TypeScript `tsx main.ts` (tsx pinned in the image; `@aulora/bot` resolved from a symlink `node_modules/@aulora/bot -> /opt/aulora/bot-sdk` created after any npm install); Python `/opt/venv/bin/python -u main.py` with the SDK installed in `/opt/venv` and `PYTHONPATH=<dir>/.deps`.

Container hardening (compose): own network `bots` shared only with `convex-backend` (no route to postgres/minio/web), `read_only: true`, tmpfs `/work` and `/tmp`, `cap_drop: [ALL]` + `cap_add: [SETUID, SETGID, CHOWN, KILL]` only for the uid switch, `security_opt: [no-new-privileges:true]`, `pids_limit`, `mem_limit`, `cpus`, `user: "0:0"` for the supervisor only (bots never run as root). Config env: `BOT_RUNNER_TOKEN`, `CONVEX_HTTP_URL`, `CONVEX_SELF_HOSTED_URL`, `BOT_RUNNER_MAX_BOTS` (default 10), `BOT_RUNNER_BOT_MEMORY_MB` (default 256).

## SDKs (stdlib only, polling transport)

Config (constructor options override env): `AULORA_TOKEN`, `AULORA_SITE_URL`, `AULORA_CONVEX_URL`. The SDK exchanges the token at `POST /bots/token`, refreshes the JWT 5 minutes before expiry (and once on a 401/`Unauthenticated` error), calls Convex via `POST {convexUrl}/api/query|mutation|action` (`{"path":"messages:send","args":{...},"format":"json"}`, `Authorization: Bearer <jwt>`; success `{"status":"success","value":...}`, failure `{"status":"error","errorMessage","errorData"}`) and polls `botEvents:poll` every 1 s (configurable; 5 s backoff after errors; resets cursor handling after reconnect — events older than the 1 h retention are lost, documented).

Surface (TypeScript `@aulora/bot` / Python `aulora_bot`, same shape, idiomatic naming):

* `Bot(options?)`, `bot.on("ready" | "message" | "messageUpdate" | "messageDelete" | "reactionAdd" | "reactionRemove" | "error", handler)`, `bot.start()` (runs until `stop()` or SIGTERM), `bot.stop()`.
* Events skip the bot's own actions (`event.self`) unless `includeSelf: true`.
* `message` handler gets a `Message` with `id, channelId, authorId, body, threadRootId, replyToId, mentionUserIds, createdAt, mentionsMe` and helpers `reply(body)`, `react(emoji)`, `delete()`, `edit(body)`.
* Client: `bot.me`, `bot.channels.list()`, `bot.messages.list(channelId, { limit })`, `.send(channelId, body, { replyToId, threadRootId })`, `.edit(id, body)`, `.delete(id)`, `bot.reactions.add(messageId, emoji)` / `.remove(...)` (the server only has `reactions:toggle`, so the SDKs toggle and correct once if the result was the wrong way round), `bot.members.list()`, `bot.call("module:function", args, kind?)` escape hatch. Method-to-function mapping is read from `packages/convex/convex/*.ts`; a call the bot lacks permission for rejects with `AuloraError` carrying the server message (e.g. `Missing permission`).
* Starter templates (`hello`): a bot that replies `pong` to `!ping` and reacts to mentions, in both languages.

## Web UI

Settings hub -> Bots (visible with `ManageBots`; read-only hint otherwise). List with status dot, create dialog (name, language, template), detail with tabs Overview / Code / Permissions / Environment / Logs / Token. Permissions tab: grouped checkboxes over `BOT_GRANTABLE_PERMISSIONS` (blocked ones listed as unavailable with a reason), channel scope (all granted channels or selected), warning copy for powerful grants (ManageMessages, Kick, Ban, MentionEveryone). Banner when `runnerStatus.online` is false ("Start the bot runner: `docker compose --profile bots up -d`"). Roles editor shows `ManageBots` with a label. Bot messages/members get a `BOT` badge.

## Quality bar

Repo checks: `bun run lint`, `bun run typecheck`, `bun run test`, `bun run test:infra`. Match surrounding style (Biome formatting, comment density). Codacy gate (zero new issues): no `obj[variable]` writes (use Map/`.at()`), `Math.random` banned (use `crypto`), no `===` on values named `token` (hash then compare/lookup, or `timingSafeEqual`), `fetch` of a URL passed as a function parameter is flagged (build URLs from validated config in one module), functions ≤ 50 nloc and ≤ 8 parameters, files ≤ 500 nloc, no `Id<...> | null` unions in exported React props (let types infer). Never log or return secrets. Every security rule above needs a test.
